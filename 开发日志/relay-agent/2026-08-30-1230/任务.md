## 目标
按用户纠正后的需求实现通路②"紧急/临时控制"：Tailscale 主通道不可达时，
Agent 与控制机 GUI 两端出站 WSS 连 Cloudflare Worker（+ Durable Object 分房间
双向转发），标准 HTTPS 传输、自有域名、合规可审计。**不做域前置/协议伪装**。

## 关键决策
1. **两端出站、Worker 被动**：Agent/GUI 都主动连 Worker，天然穿透 NAT，无需公网 IP/端口
2. **Durable Object 按 node_id 分房间**：Free 计划 SQLite 后端可用，官方推荐的多 WS 协调方案
3. **协议零新增**：JSON 帧语义对齐 proto Command/CommandResult；Agent 复用现有 executor
   与 commandType 白名单；status 用数字枚举（前端踩坑教训的直接延续）
4. **离线暂存补发**：GUI 指令在 Agent 离线时存 DO SQLite，上线按 seq 补发（对齐
   "离线本地缓存+补传"理念）
5. **与主通道并存**：relay 是辅助兜底，不替代 gRPC CommandStream；遥测实时展示不抢主通道入库

**遗留 3（意外发现的根因 bug）：DO 空闲冻结丢内存态 → 链路静默中断**
- 症状：节点 relay 连接 ESTAB 且日志正常，但 GUI 下发的命令永远到不了 Agent；
  每次都"重新部署 Worker 或重启 agent 后立即恢复，几分钟后复发"
- 定位：Worker 日志铁证——agent 的 ping/telemetry 帧显示 `fromAgent: false`，
  说明 `ws === this.agentWs` 恒 false。**Durable Object 空闲约 30s 被 Cloudflare
  冻结，唤醒后内存字段（agentWs/guiWs）全部清空，但 WebSocket 连接仍存续** →
  心跳被当 GUI 帧、指令全落 SQLite 暂存、链路静默中断
- **根治：WebSocket Hibernation API + tags**
  - `state.acceptWebSocket(ws, ['agent'|'gui'])`——tag 由运行时持久化
  - 转发/判活全改为 `state.getWebSockets('agent'/'gui')` 而非内存字段
  - 角色判定改为 URL path（/agent /gui）而非自定义 header（跨边界可能丢失）
  - alarm 也依赖 getWebSockets，冻结唤醒后自动续租期
- **验证**：基线、120s、240s 三次冻结恢复测试全部通过（RELAY_E2E_OK 三连）
- **教训**：Durable Object 房间类若持有连接集合，必须用 Hibernation tags，
  内存变量在冻结后必丢——这是 CF DO 的硬特性，不是偶发
