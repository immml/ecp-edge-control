## 0. 一句话定位

一个**自有边缘设备的远程运维管理平台**（fleet management）。控制面按需上线，节点通过 Tailscale 自组网互联，Cloudflare Worker 仅作为地址映射表。管理对象是**你自己拥有或已获授权的边缘节点**。

---

## 1. 合规边界（硬约束，不可协商）

本项目的能力边界：

| 做 | 不做 |
|---|---|
| 自有/授权设备的远程 SSH、文件、网络、容器管理 | 未授权设备的任何接入或控制 |
| 节点注册鉴权（预置 Key + 硬件指纹绑定） | 免杀、隐藏进程/端口、规避 EDR/杀软 |
| 完整操作审计日志 | 权限提升利用、凭据窃取 |
| mTLS 双向证书、凭据加密存储 | 任何形式的隐蔽持久化 |
| 敏感操作二次确认 | 匿名/不可追溯的操作通道 |

**"上线即控"的实现方式**：节点预置注册 Key + 上报硬件指纹，控制面完成 Key↔指纹绑定后签发客户端证书。之后节点重启、重装、断网重连均用同一套凭据**自动完成重认证，无需人工审批**；但首次绑定与每次重认证**全部写入审计日志**，且 Key 可吊销、指纹变更需复核。

## 3. 由需求推导的关键架构约束

1. **控制面非长驻** → 节点必须自治：本地配置持久化、本地状态缓存、本地告警规则引擎。控制面是"管理终端"而非"必需品"。
2. **双向注册** → Worker KV 需存两张表：`node_registry`（node_id → tailscale_ip / 指纹 / 状态 / last_seen）与 `control_plane_registry`（instance_id → 地址 / 公钥 / last_seen）。双方启动时写、退出时清理、定期心跳续期。
3. **Agent 非 root** → 功能分级：用户态可执行（状态采集、SSH 会话代理、文件管理、日志读取、容器只读）；需提权（iptables、systemd、docker 写操作）走**脚本生成 + 人工 sudo** 降级路径。
4. **ARM64 优先** → 所有容器镜像必须支持 linux/arm64；控制面若在 Orange Pi 上运行，PG/Redis/Mosquitto 均需 arm64 镜像（均为官方支持）。
5. **完全隔离** → 端口规划避开 1Panel（默认 8080/8081）与常见业务端口，Agent 使用 7443（gRPC+TLS）/ 7883（MQTT over TLS）/ 7444（节点本地 CLI）。

## 4. 一期 / 二期划分

**一期（本次交付）**
- 控制面 Server（Go）：节点注册鉴权、心跳状态、配置下发、审计日志、REST API、gRPC 服务
- Agent（Go，arm64 + amd64）：注册/保活、状态采集、SSH 会话代理、文件操作、Tailscale 纳管、网络信息与控制、容器基础操作、本地告警规则引擎 + 飞书 Webhook、节点本地 CLI
- Web 控制台（Vue 3）：节点列表与详情、Web SSH 终端、文件管理器、网络配置、Tailscale 状态、容器管理、审计日志查询、用户与角色管理
- Worker 引导服务（KV 映射表 + REST 端点）
- docker compose 一键部署 + 端到端真机验证（Orange Pi）

**二期**
- FRP 管理
- 完整 OTA 灰度/分批/回滚
- 多站点云管控汇聚
- 时序指标持久化（VictoriaMetrics）
- 敏感操作审批流
