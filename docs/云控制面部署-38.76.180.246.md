## 部署记录（可复现）

1. Windows 侧交叉编译 Linux 控制面：
   Linux (Git Bash)：
   ```bash
   cd server && CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -o dist/ecp-server-linux-amd64 ./cmd/server
   ```
2. 上传 `/opt/ecp-server/{ecp-server, server.yaml}`（paramiko SFTP，scripts/cloud_upload.py）
3. 生成注册密钥（**必须最后一步**，重置库后要重跑）：
   Linux (云)：
   ```bash
   cd /opt/ecp-server && ECP_CONFIG=/opt/ecp-server/server.yaml ./ecp-server keygen cloud-node
   # REGISTRATION_KEY=xxx（用于节点接入）
   ```
   注意：`keygen` 必须作为第一个参数（`ecp-server keygen`），配置用 ECP_CONFIG 环境变量；
   `-c file keygen` 这种写法会被当成 serve 模式！
4. systemd 单元 + ufw 放行 + 启动（脚本流程见下）；首次启动日志可 grep 初始 admin 密码：
   ```bash
   journalctl -u ecp-server | grep 初始超管
   ```

## systemd 单元

```ini
[Unit]
Description=ECP Control Plane (Cloud Server)
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/ecp-server
Environment=ECP_CONFIG=/opt/ecp-server/server.yaml
EnvironmentFile=/opt/ecp-server/ecp.env
ExecStart=/opt/ecp-server/ecp-server
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

## 节点切换（把 Pi agent 切到云控制面）

1. `agent.yaml`：`control_plane.endpoints` 改为 `38.76.180.246:7443`
2. `registration.key`：写入云端 keygen 的 REGISTRATION_KEY（**不要带换行**，
   `printf '%s' "$key" > registration.key`；agent 新版本已做 TrimSpace 兼容）
3. `agent.yaml` registration 段用 `key_file:` 指向该文件（旧版用内联 `key:` 不含换行也可）
4. 删除旧 client.crt/client.key，**放入云端 CA**（`/opt/ecp-server/data/certs/ca.crt` 拷到
   节点配置目录为 ca.crt）——没有 CA 时 TLS 握手失败（云端日志 `TLS handshake error`）
5. 重启 agent → 用新 key 注册 → 云端签发 client.crt（CN=node_id）→ mTLS 常连接入

## 排障速查

| 现象 | 原因与处理 |
|---|---|
| 节点连接超时、云端日志 `TLS handshake error` | 节点缺云端 ca.crt → 拷贝 CA 到节点 |
| 注册被拒 `registration key invalid` | key 与库不匹配：重新 keygen 并更新节点；注意文件换行 |
| keygen 报"端口被占用" | `-c file keygen` 被当成 serve：改用 `ECP_CONFIG=... ./ecp-server keygen` |
| 紧急通道 bad handshake | node_id 变更后 relay token 未重新派生 → 派生更新 |
